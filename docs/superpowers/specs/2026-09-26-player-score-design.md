# Очки игрока, уровни и ранги — дизайн

**Дата:** 2026-09-26
**Ветка:** `feat/player-score`
**Статус:** утверждён в брейншторминге, ждёт ревью спеки
**Макеты:** `.superpowers/brainstorm/1767-1790423005/content/` (`win-screen-v3.html`, `home-game-stats.html`) — локальные, в git не входят

## 1. Цель

Дать игроку ощущение прогресса и награды: очки за каждую верную цифру прямо во время партии,
накопление между партиями, уровни и ранги со значками, рекорды по очкам и праздничный экран победы
с анимацией начисления и конфетти.

**Решения пользователя (зафиксированы):**

- Модель очков — по образцу Sudoku.com: очки за каждую верную цифру, скорость ввода встроена в
  формулу. Фиксированные 100/200/300 за победу — **не делаем**.
- Штраф за ошибку — да.
- Очки копятся между партиями; есть уровни игрока, ранги со значками и рекорд по очкам на каждом
  уровне сложности.
- Очки проигранной и брошенной партии **сгорают** — в баланс идут только победы.
- «Сбросить статистику» сбрасывает и очки/уровень/ранг/рекорды.
- Во время игры: счёт в шапке + всплывающие «+N» над клеткой.
- Экран победы: набегающий счёт, «перетекание» в полоску уровня, конфетти.

**Вне объёма:** трата очков, подсказки, ежедневные задания, достижения, таблица лидеров, e2e-тесты
(Playwright в проекте не установлен).

## 2. Правила начисления

Источник модели — реверс-инжиниринг Sudoku.com:
[формула](https://tommie.github.io/a/2025/02/sudoko-com-scoring),
[максимумы](https://tommie.github.io/a/2025/03/sudoku-com-max-score).

### 2.1. Константы по уровню сложности

| Сложность | База `B` | Шаг (−за каждые 5 с) | Минимум |
|---|---|---|---|
| easy | 50 | 5 | 5 |
| medium | 150 | 15 | 15 |
| hard | 210 | 21 | 21 |

Шаг и минимум = `B / 10`. Окно убывания — 5 секунд. Хранятся одной таблицей
`SCORE_RULES: Record<Difficulty, { base, step, min }>`.

### 2.2. Верная цифра

```
dt         = elapsedSeconds − lastCorrectAtSecond
cellPoints = max(min, base − step × floor(dt / 5))
multiplier = max(1, 5 × [строка закрыта] + 5 × [столбец закрыт] + 5 × [квадрат закрыт])
gained     = multiplier × cellPoints
```

- «Закрыта» = все 9 клеток линии/квадрата равны `solution` (ошибочная цифра линию не закрывает).
- `dt` меряется игровым таймером, поэтому пауза и уход с экрана его не накручивают.
- `lastCorrectAtSecond` обновляется **только** на верной цифре, за которую начислены очки.
  Ошибка таймер не сбрасывает (угадывание невыгодно). Для первой цифры партии отсчёт идёт от 0.
- Заметки на счёт не влияют.

### 2.3. Ошибка

`score = max(0, score − base)`. Каждая ошибочная постановка (включая повторную) штрафуется —
так же, как каждая снимает жизнь.

### 2.4. Анти-фарм

Клетка приносит очки только при **первой** верной постановке за партию (`scoredCells[row][col]`).
Стереть/отменить и поставить заново → 0 очков, `lastCorrectAtSecond` не меняется. Undo счёт не
возвращает и не отнимает (по аналогии с жизнями).

### 2.5. Итог партии

- Победа → `score` партии пишется в журнал и прибавляется к балансу.
- Поражение и брошенная партия → в журнал пишется `score: 0` (очки сгорают).

## 3. Модель данных

### 3.1. `GameState` (localStorage, `sudoku:game`)

Новые поля:

```ts
score: number;                   // счёт текущей партии, ≥ 0
lastCorrectAtSecond: number;     // elapsedSeconds последней оплаченной верной цифры
scoredCells: boolean[][];        // 9×9, клетка уже принесла очки
lastScoreEvent: ScoreEvent | null; // для всплывашек; не восстанавливается

interface ScoreEvent {
  id: number;         // монотонный счётчик — ключ для перезапуска анимации
  row: number;
  col: number;
  delta: number;      // +gained или −штраф (фактический, с учётом пола 0)
  multiplier: number; // 1 для обычной цифры и для ошибки
}
```

**Мягкая миграция без роста `GAME_SCHEMA_VERSION`:** при загрузке сохранённой партии, в которой
новых полей нет, они заполняются значениями по умолчанию, партия не отбрасывается:

| Поле | Значение по умолчанию |
|---|---|
| `score` | `0` |
| `lastCorrectAtSecond` | текущий `elapsedSeconds` |
| `scoredCells` | `true` для клеток, где `currentGrid == solution` и клетка не исходная |
| `lastScoreEvent` | `null` (и при любом восстановлении тоже) |

Решение оформляется как **ADR-0007** («Мягкая миграция GameState: новые поля со значениями по
умолчанию вместо роста схемы») — это прецедент для следующих фич.

### 3.2. `CompletedGame` (IndexedDB, журнал `games`)

```ts
score?: number; // очки партии; для lost/abandoned — 0; старые записи без поля считаются 0
```

`DB_VERSION` не меняется — IndexedDB не валидирует форму значений, индексы не затрагиваются.

### 3.3. Прогресс — вычисляется, не хранится (ADR-0002)

| Величина | Как считается |
|---|---|
| Баланс | `Σ score` по всему журналу (независимо от периода статистики) |
| Уровень | уровень `L` начинается с `5000 × (L−1) × L / 2` очков; на переход `L → L+1` нужно `5000 × L` |
| Ранг | по таблице 3.4 от уровня |
| Рекорд очков | `max score` среди побед на каждой сложности (в выбранном периоде — на экране статистики) |

Пороги уровней: 2 — 5 000, 3 — 15 000, 4 — 30 000, 5 — 50 000, 6 — 75 000, 10 — 225 000. Потолка нет.

### 3.4. Ранги

| Уровни | Ранг | Значок (SVG) | Цвет |
|---|---|---|---|
| 1–2 | Новичок | росток | `#37b26b` |
| 3–4 | Ученик | открытая книга | `#3f9fd8` |
| 5–7 | Любитель | молоток (клиновидный боёк) | `#2f6fed` |
| 8–11 | Знаток | шапочка выпускника | `#7b5cf0` |
| 12–16 | Эксперт | бриллиант | `#12a4b6` |
| 17–24 | Мастер | медаль | `#e8a23a` |
| 25+ | Гроссмейстер | корона | `#d49a12` |

Хранится одним массивом `RANKS` (отсортирован по `fromLevel`); ранг — последний элемент с
`fromLevel ≤ level`. Значок — белый контурный глиф (stroke 1.8, viewBox 24) в круге с градиентом
цвета ранга. Пути глифов — из макета `win-screen-v3.html`.

## 4. Архитектура

```
src/state/scoring.ts        чистые функции: SCORE_RULES, scoreCorrectEntry, mistakePenalty,
                            completedUnitsMultiplier
src/state/progress.ts       чистые функции: levelForTotal, levelStart, rankForLevel, RANKS,
                            levelUpSegments (сегменты анимации полоски), bestScoresByDifficulty,
                            totalScore
src/state/gameReducer.ts    PLACE_DIGIT начисляет/штрафует через scoring.ts, пишет lastScoreEvent;
                            NEW_GAME инициализирует поля; RESTORE чистит lastScoreEvent
src/state/storage/localGame.ts   мягкая миграция при loadGame (withScoreDefaults)
src/state/storage/historyDb.ts   CompletedGame.score
src/state/RecordsContext.tsx    + bestScores, totalScore (единственный контекст агрегатов журнала)
src/state/GameContext.tsx       запись score в журнал; снимок «до» (prevTotal, prevBestScore)
                                для экрана победы — тем же приёмом, что prevBest времени
src/components/rank/RankBadge.tsx       значок ранга (SVG-глифы + цвет)
src/components/rank/LevelProgress.tsx   уровень + ранг + полоска (главный экран, статистика)
src/components/header/ScoreDisplay.tsx  счёт в центре шапки, набегание + bump/hurt
src/components/board/ScorePopup.tsx     всплывашка над клеткой по lastScoreEvent
src/components/confetti/                canvas-движок частиц (свой, без зависимостей)
src/components/winscreen/useWinSequence.ts  шаги анимации экрана победы, skip, reduced-motion
src/hooks/useCountUp.ts                 набегание числа на requestAnimationFrame
```

- Reducer остаётся чистым: вся арифметика — в `scoring.ts`, reducer только применяет результат.
- `RecordsContext` уже грузит журнал при старте — туда добавляются `bestScores` и `totalScore`;
  уровень и ранг вычисляются из `totalScore` функциями `progress.ts` там, где нужны.
- `prefers-reduced-motion` читается одним хуком `usePrefersReducedMotion` и отключает набегание,
  всплывашки (остаётся только смена числа) и конфетти.

## 5. UI

### 5.1. Шапка игры

Счёт партии («Очки» / число) — по центру верхней строки между `‹` и `⚙`. Строка
«Уровень / Жизни / Время» не меняется. При начислении число набегает (~450 мс) с «пульсом»; при
штрафе — короткое покачивание красным.

### 5.2. Всплывашки над клеткой

По новому `lastScoreEvent.id` над клеткой появляется и уплывает вверх (~0.9 с, `pointer-events: none`):

| Событие | Вид |
|---|---|
| Верная цифра | синее «+150» |
| Закрыта линия/квадрат | оранжевое крупное «×5» + «+750» под ним (~1.2 с); закрытые клетки коротко подсвечиваются |
| Ошибка | красное «−150» |
| Повторная постановка оплаченной клетки | всплывашки нет |

### 5.3. Экран победы

Существующая карточка (иконка, заголовок, время/сложность/жизни, кнопки) сохраняется; между
заголовком и статистикой добавляются блоки. Последовательность (`useWinSequence`):

1. 0.3 с — «Очки за партию» набегают 0 → итог (~1.2 с, ease-out), в конце «pop» + конфетти
   из двух нижних углов.
2. Бейджи: `★ Рекорд очков` (новый) и существующий `★ Новый рекорд` (время) — если заслужены.
3. Блок прогресса: значок ранга, «Уровень N», имя ранга, полоска, «X / Y до ур. N+1».
   Полоска заполняется от старого баланса к новому.
4. Переход уровня: полоска до 100% → вспышка → номер уровня «pop» + малый залп конфетти →
   полоска с нуля до остатка. Несколько уровней — повтор, сегменты быстрее.
5. Новый ранг: значок меняется (scale + свечение) + большой залп конфетти + строка
   «Новый ранг: Любитель».

- Тап по карточке — сразу финальное состояние. Кнопки активны с первого кадра.
- `prefers-reduced-motion` — сразу финальное состояние, без конфетти.
- **Поражение:** счёт партии показан зачёркнутым с подписью «Очки сгорают при поражении», блок
  прогресса статичный, конфетти нет.

### 5.4. Главный экран

Под заголовком — карточка профиля (`LevelProgress`): значок, «Уровень 6», ранг, полоска,
«89 810 очков · до ур. 7: 15 190». Тап — переход на статистику.

### 5.5. Статистика

- Сверху карточка прогресса: значок, «Уровень 6 · Любитель», баланс, полоска,
  «след. ранг: Знаток на ур. 8» (на последнем ранге строки нет). Не зависит от периода.
- В строках сложностей под лучшим временем — «★ 21 640 очков» (рекорд очков в периоде, `—` если нет).
- Диалог «Сбросить статистику» предупреждает, что сбросятся также очки, уровень и ранг.

### 5.6. `data-testid`

`game-score`, `score-popup`, `win-score`, `win-score-burned`, `score-record-badge`,
`level-progress`, `level-number`, `rank-name`, `rank-badge`, `new-rank`, `home-profile`,
`stats-progress`, `stat-diff-<difficulty>-best-score`.

## 6. Ошибки и крайние случаи

- Журнал недоступен → баланс 0, уровень 1 (как статистика сейчас — игра не ломается).
- Запись в журнал не удалась → очки партии теряются, UI экрана победы всё равно показывает
  анимацию от снимка «до» (баланс «после» = до + счёт партии, считается локально).
- Финальная цифра партии всегда закрывает строку, столбец и квадрат → ×15; это ожидаемо.
- Повторная ошибка в той же клетке штрафуется снова.

## 7. Тестирование

**Unit (Vitest):**
- `scoring.test.ts` — база по сложностям; убывание на границах 4/5/44/45/200 с; минимум;
  множители ×1/×5/×10/×15; ошибочная цифра не закрывает линию; штраф с полом 0.
- `gameReducer.test.ts` — начисление и `lastScoreEvent`; клетка платит один раз (erase/undo +
  повторная постановка = 0); undo не меняет счёт; ошибка не сбрасывает `lastCorrectAtSecond`;
  NEW_GAME обнуляет поля.
- `localGame.test.ts` — старая партия без новых полей восстанавливается с корректными значениями по
  умолчанию; `lastScoreEvent` сбрасывается.
- `progress.test.ts` — уровень на границах (4 999 → 1, 5 000 → 2, 14 999 → 2, 15 000 → 3); ранг
  на границах таблицы; `levelUpSegments` без перехода, с одним и с двумя переходами; рекорды
  очков; записи без `score` = 0.
- `GameContext`/журнал — победа пишет `score`, поражение и брошенная — 0.

**Компоненты (Testing Library, jsdom):** экран победы (reduced-motion/тап → финальные значения,
бейдж рекорда очков, строка нового ранга, зачёркнутый счёт при поражении); счёт в шапке;
карточка профиля и переход в статистику; рекорды очков в статистике.

**Вручную (скилл `run`, реальный браузер):** всплывашки, экран победы с переходом уровня и ранга,
конфетти, обе темы, reduced-motion. Canvas и тайминги в jsdom не проверяются.
