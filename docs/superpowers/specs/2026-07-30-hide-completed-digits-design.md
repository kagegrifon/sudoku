# Скрытие полностью расставленных цифр

**Дата:** 2026-07-30
**Статус:** утверждено

## Проблема

Когда игрок расставил все девять вхождений какой-то цифры, она больше не нужна — ни для
ввода в клетку, ни как кандидат в карандашных пометках. Сейчас цифра продолжает занимать
кнопку на нампаде и висеть в заметках: визуальный шум и провокация бесполезных тапов.

## Решение

Полностью расставленная цифра скрывается в двух местах: на кнопке нампада и в карандашных
пометках всех клеток поля.

### Критерий завершённости

Цифра завершена, когда на поле девять её **верных** вхождений — совпадающих с решением.
Это ровно то, что уже считает
[`countRemainingDigits`](../../../src/state/remainingDigits.ts): ошибочно вписанная цифра
слот не закрывает, поэтому неправильный ход не скроет кнопку раньше времени.

Побочный эффект: исчезновение кнопки косвенно подтверждает правильность последнего хода.
Принято осознанно — механика жизней в игре и так сообщает об ошибке сразу.

### Нампад

Кнопка становится невидимой и некликабельной, но **слот в раскладке сохраняется**: остальные
цифры не смещаются, мышечная память игрока не ломается. Технически — `visibility: hidden`,
а не `display: none`: это работает одинаково во flex-раскладке (portrait) и в сетке 3×3
(landscape).

Счётчик остатка у завершённой цифры не рендерится — нулевой остаток избыточен.

### Карандашные пометки

Пометки скрываются **только при отрисовке**. Массив `notes` в состоянии игры не меняется:
если игрок отменит ход или сотрёт цифру, пометки вернутся сами, без специальной логики
восстановления и без записей в историю undo.

Если после скрытия в клетке не осталось видимых пометок, клетка отображается пустой.

### Настройка

Тумблера нет — поведение всегда включено. Фича не спорна и не требует выбора: расставленная
цифра бесполезна по правилам судоку.

## Архитектура

Единственная новая абстракция — производная функция рядом с существующим счётчиком:

```ts
/** Цифры, у которых расставлены все девять верных вхождений. */
export function collectCompletedDigits(
  remainingByDigit: Record<number, RemainingDigit>,
): Set<number>
```

`Set` выбран потому, что оба потребителя (`NumberPad`, `Cell`) делают проверку членства.

Поток данных повторяет уже существующий путь `remainingByDigit`:

```
countRemainingDigits → collectCompletedDigits → GameContext (useMemo)
                                                    ├→ GameScreen → NumberPad
                                                    └→ GameScreen → Board → Cell
```

Набор вычисляется один раз в `useMemo` и передаётся вниз по ссылке, поэтому `memo` на `Cell`
не деградирует.

## Совместимость

`GAME_SCHEMA_VERSION` и `SETTINGS_SCHEMA_VERSION` не меняются: новых сохраняемых данных нет,
всё вычисляется из уже существующих `currentGrid` и `solution`. Сохранённые партии
открываются как обычно.

Тип изменения по SemVer — **patch**: версия `0.1.1` → `0.1.2`.

## Отклонённые альтернативы

- **Физическое удаление цифры из `notes`.** Требовало бы записи в историю ради корректного
  undo и делало операцию необратимой при стирании цифры с поля. Скрытие при отрисовке даёт
  тот же результат для игрока дешевле.
- **Кнопка исчезает, остальные растягиваются.** Цифры «прыгают» по мере заполнения поля,
  ломая мышечную память.
- **Кнопка просто приглушается.** Не решает проблему визуального шума — цифра остаётся на
  экране.
- **Учитывать любые девять вхождений, включая ошибочные.** Убрало бы косвенный спойлер, но
  разошлось бы со счётчиком оставшихся цифр и скрывало бы кнопку, которая игроку ещё нужна
  для исправления ошибки.

## Тестирование

Unit-тесты (Vitest):

- `collectCompletedDigits` — пустой набор на старте; цифра попадает в набор ровно при девяти
  верных вхождениях; ошибочно вписанная девятая цифра набор не пополняет.
- `NumberPad` — завершённая цифра присутствует в DOM, помечена `data-completed`, `disabled`;
  соседние кнопки не затронуты; счётчик остатка у неё не рендерится.
- `Cell` — пометка завершённой цифры не отображается, остальные пометки на месте.

Селекторы — по `data-testid`.
